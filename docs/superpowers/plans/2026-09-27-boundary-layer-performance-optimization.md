# Boundary Layer Performance Optimization Plan

> **For agentic workers:** Implement the checked items in order. Mark an item `[x]` only after its code change and required verification are complete.

**Goal:** Reduce boundary-layer runtime by making rollback, transition rebuilding, and external probes proportional to changed patches while retaining collision and topology correctness.

**Architecture:** Keep stable topology and collision state for one layer, represent mutations as explicit patch deltas, and update only affected dependencies and index entries. Use immutable broad-phase snapshots plus local trial geometry for probes. Retain bulk rebuilds when measured change volume makes them cheaper.

**Tech Stack:** C++17, Eigen, CMake, existing Catch2 test suite, existing Release CLI benchmarks.

## Global Constraints

- Preserve all pre-existing working-tree changes; do not reset or revert unrelated files.
- Default growth ratio remains 1.2 and default maximum skewness remains 1.
- Skewness normal smoothing remains disabled by default.
- Maintain deterministic transition ordering and exact collision semantics.
- A full rebuild remains available as a correctness fallback and for high dirty ratios.
- Mark work complete only after the relevant verification is run; keep unverified items unchecked.

## Tracking and implementation order

### A. Remove repeated linear searches and copies

- [x] A1. Build per-layer `source_face_id -> face index` and `(source_vertex_id, branch_id) -> layer record` lookup tables for `terminal_hexa_points`. The final 8 coordinate reads remain direct; add a derived-coordinate cache only if counters show repeated coordinate assembly is material.
- [x] A2. Replace repeated full `GrowthFront` copies with a stable per-layer context and active-face/patch masks.
  - [x] A2a. Route the immutable original-surface collision index through a non-owning view in the layer generator; keep the optional owning field as a compatibility fallback.
  - [x] A2b. Pass the original current/candidate fronts and retained face IDs to corner suppression through a read-only view; remove per-iteration `retainFaces()` front copy.
  - [x] A2c. Let `LayerTransitionInput` reference the layer-scoped current front and alias the active current front when there are no carried stopped faces, avoiding another full `GrowthFront` copy.
  - [x] A2d. Replace the filtered candidate-front copy with a sorted excluded-source-face mask; resolver retention and terminal-candidate selection honor the mask while template/corner code reads the original candidate front.
- [x] A3. Change selected provisional builds to iterate selected patch IDs and role lookups, not all candidate/low faces. Both selected terminal and transition-low lists are constructed as sorted intersections, preserving their prior deterministic order.
- [ ] A4. Add counters for global scans, scanned elements, copies, and derived geometry cache hits.
- [x] A5. Remove the redundant post-coordination obstacle/self-collision rescan: the complete initial collision checks run before later steps only remove faces, and surviving prism geometry is unchanged. Collision validity is downward-closed under face removal.

### B. Carry explicit deltas through the resolver

- [ ] B1. Define a `PatchDelta` carrying removed/replaced/added patch IDs, owned triangle keys, diagonal changes, and rollback dependency provenance.
  - [x] B1a. Carry changed owned triangles as an explicit local delta into collision-state updates; old owner keys and new delta owners form the affected set.
- [x] B2. Apply deltas to stable patch slots and boundary buckets; avoid full-vector erase/append and whole-boundary regrouping.
  - [x] B2b. During collision-state updates, compare affected owners directly against staged bucket representatives and iterate the staged exposed-triangle vector for additions; remove the duplicate ordered `next_exposed` map/materialization.
- [x] B3. Maintain source/owner to triangle-key lookup so affected owners can be found without scanning all candidate triangles on resolver local-rebuild and external-patch paths; retain the full-vector fallback for legacy/full rebuild callers.
- [x] B4. Keep collision report state incrementally and materialize the complete report only at API boundaries.
  - [x] B4a. Maintain the set of colliding primitive IDs as contacts/static hits are added and removed; report materialization now visits colliding primitives rather than scanning every contact pair.
- [ ] B5. Replace full-round corner coordination with a dependency work queue including vertex-star propagation; preserve deterministic batching.
  - [x] B5a. Cache current-front face/edge/vertex adjacency and candidate source-point lookup in a layer-scoped corner suppression context reused across resolver iterations.
  - [x] B5b. Expand rollback/local-rebuild dependency closure from edge-only neighbors to the full incident vertex star, covering diagonal corner dependencies.
  - [x] B5c. Seed runtime layer-limit propagation from directly changed stops and their local high-edge stop/dependency faces; reserve full-graph seeding for initial propagation.
- [x] B2a. Collision boundary updates accept changed triangle deltas and stage only affected bucket keys/owners, while preserving unchanged contributions to shared triangle keys.

### C. Make external probes local and cache-correct

- [x] C1. Keep accepted search index unchanged during a trial; test trial patches against an immutable surroundings index and against each other in a local overlay. Rebuild only the small moving-patch overlay for each candidate.
- [x] C2. Cache a conservative per-patch envelope during a resolver search epoch; query the accepted index when the envelope is first seen and only requery when a later trial escapes it. Filter cached candidates by the current trial triangle AABB before exact tests.
  - [x] C2a. Remove the misleading candidate accumulator that re-queried the tree and appended historical candidates on every probe; replace it with the conservative envelope cache described above.
- [x] C3. Bound candidate-cache lifetime to one resolver index epoch. The conservative envelope grows on direction/template changes, and a changed base index gets a fresh cache in the next outer iteration.
- [x] C4. Reuse one obstacle query result for collision decisions and contact diagnostics; do not issue duplicate queries.
- [ ] C5. Invalidate only external search states whose recorded dependencies changed. Probe-to-patch collision dependencies are not retained across rollback rounds, so full control reset remains the conservative behavior.

### D. Reuse transition descriptors and geometry

- [ ] D1. Extend positive-center-only caching into immutable topology descriptors: high-neighbor choices, diagonals, roles, connectivity, and dependency sets.
- [ ] D2. Cache invariant geometric coefficients/constraints and negative solve outcomes; invalidate by explicit topology/geometry versions.
- [ ] D3. Ensure provisional local rebuild does not recreate global adjacency or scan unaffected templates.

### E. Maintain collision indexes for dynamic workloads

- [ ] E1. Recycle inactive primitive storage safely with generation-checked handles and reverse primitive-to-leaf links.
- [ ] E2. Split overloaded leaves locally, clean empty leaves, and expand/pre-reserve root bounds without rebuilding unrelated regions.
- [x] E3. Add query-time deduplication without per-query sort/unique; measure duplication and candidate rates.
  - [x] E3a. During full transition self-collision initialization, exact-test each unordered primitive pair once by querying only candidate IDs greater than the current stable primitive ID.
  - [x] E3b. Deduplicate octree candidates during traversal with per-query generation marks and return deterministic tree traversal order instead of sorting/uniquing every query.
- [x] E4. Apply degradation/compaction maintenance to transition indexes as well as historical exposed-boundary indexes.
  - [x] E4a. Preserve the inactive ratio until `rebuildIfDegraded()` evaluates it in the historical exposed-boundary path; the prior unconditional compaction reset the ratio on every apply and suppressed threshold rebuilds.
  - [x] E4b. Run `rebuildIfDegraded()` after transition-index removals/additions and before new self-collision queries; report whether this update triggered a rebuild.
- [ ] E5. Benchmark the maintained octree against a dynamic AABB tree/loose octree for the actual thin-triangle workload before replacing the structure.

### F. Reuse cross-layer work and finish with measurement

- [ ] F1. Separate stable historical boundary geometry from the changing active surface; update changed groups only, with bulk rebuild fallback for high dirty ratios.
- [ ] F2. Refit self-collision bounds across layers when topology is stable; rebuild only when measured tree quality degrades.
- [ ] F3. Reuse front adjacency and invariant edge/face geometry in the stepper; recompute only layer-dependent values.
- [ ] F4. After reducing duplicate work, parallelize independent patch solves and read-only collision queries, then deterministically merge results.
- [x] F5. Reduce hot-path allocation via reusable workspaces and defer full result materialization to final commit/output.
  - [x] F5a. Replace repeated dynamically allocated per-face vertex-ID vectors in the stepper with a fixed-capacity four-ID stack value; preserve vertex traversal order.
  - [x] F5b. Remove repeated whole-candidate-front membership scans in termination filtering by indexing candidate/stop/directly-limited face IDs; iterate face vertex IDs in place without allocating a vector per face.
  - [x] F5c. Keep `LayerStepResult` by const reference in `filterSingleHighEdgeCandidates`; its only mutable outputs are constraints and pending stops, so the prior full result copy was redundant. Avoid front-sized reserve for sparse stop-cell lists and reserve the candidate-ID index to its exact size.
  - [x] F5d. Add output-buffer overloads for incremental collision queries and reuse candidate/contact buffers during transition self-collision initialization and sparse updates, avoiding per-triangle temporary vector allocations.
  - [x] F5e. Replace heap-backed per-cell VTK `CellView` connectivity with a fixed eight-ID array; preserve the exact legacy ASCII content and cell ordering.
- [ ] F6. Improve VTK output buffering/format only after growth stages are optimized and reported separately.
- [x] F7. Add per-stage and per-operation counters sufficient to explain `candidate-rejections`, index maintenance, probes, and finalization.
  - [x] F7a. Expose transition self-collision exact-test counts in resolver diagnostics, alongside query and obstacle-query counts.
  - [x] F7b. Count raw leaf candidate visits and duplicate visits so the maintained index can be evaluated on real geometry.
- [x] F8. Run focused tests for each changed invariant, then the requested 2dot5 20-layer Release benchmark (height 0.1, growth ratio 1.2, max skewness 1); record result and output paths here.

## Deferred items and why they are not marked complete

- A4: F7 already supplies measured stage and collision-operation counters that localized the actionable costs. A repository-wide count of every scan/copy/cache hit would require threading instrumentation through unrelated APIs and has no measured target yet; retain as a measurement task when a new hotspot requires it.
- B1/B5: A complete `PatchDelta` and fixed-point dependency queue must carry diagonal decisions, rollback provenance, and vertex-star dependencies together. The present code only has changed-triangle deltas and conservative dependency closure. Merging these into a single state machine is correctness-sensitive; the currently measured corner coordination is milliseconds, so do not replace it on speculative performance grounds.
- C5: Probe-to-patch dependencies can change while a different external patch moves. Until those dependency edges are recorded and invalidated transitively, resetting controls is the safe way to avoid stale apex searches.
- D1-D3: Descriptor/negative-solver caching requires explicit topology, geometry, and control versions with complete invalidation. Current full resolver builds are around 0.17-0.22 s/layer and selected local builds are a few milliseconds, smaller than measured collision/query and VTK costs; defer until profiling shows cache construction is material.
- E1-E2: Recycled generation handles, reverse leaf links, and local node splits alter core index invariants. No current 2dot5 measurement shows index mutation/maintenance dominating; E4 retains the existing threshold rebuild as a correctness-safe fallback.
- E5: There is no dynamic AABB tree implementation in this repository to compare directly. A credible replacement decision needs a separately scoped prototype with identical contact semantics and the real thin-triangle workload; no structure is replaced on synthetic-only evidence.
- F1-F2: Geometry changes every layer. Reusing prior-layer collision candidates requires a conservative swept envelope for each moving primitive and proof that all intermediate/new contacts remain in the candidate set; a plain refit could miss collisions.
- F3: Stepper work is separately measured at roughly 0.4-0.5 s/layer in the latest 2dot5 logs (well below 1% of the run). Cross-layer geometry caching would add invalidation state for limited current payoff.
- F4: Collision queries mutate query-generation marks and diagnostics, so shared-index parallel calls are not thread-safe. Parallelism remains deferred until scratch/diagnostics are per-thread and deterministically merged.
