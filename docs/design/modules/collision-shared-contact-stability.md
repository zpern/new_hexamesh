# 合法共享接触的数值稳定性设计

## 1. 问题与证据

`2dot5_cf` 在 Release、`first_height=0.1`、只生成一层时，58,139 个质量合格候选中有 17,705 个源面被标记为 `Collision`，最终只提交 40,434 个体单元。

逐阶段和拓扑关系诊断结果如下：

| 检测阶段 | 停止面数 | 拓扑关系 |
|---|---:|---|
| 原始表面障碍 | 5,769 | 同源面 2,147、共边邻面 2,810、共点邻面 812、无关面 0 |
| 同层自碰撞 | 11,936 | 共边候选 7,421 对、共点候选 1,831 对、无关候选 0 |

原始表面命中的 8,588 个三角形接触中，8,554 个被分类为 `ProperIntersect`，且全部来自候选侧面。同层命中的 10,973 个三角形对中，10,924 个被分类为 `ProperIntersect`，其中 9,508 个是顶面—相邻侧面接触。

将 `first_height` 从 `0.1` 缩小到 `0.001` 后，`Collision` 反而从 17,705 增加到 39,705，生成单元从 40,434 降至 18,437；所有命中仍然只发生在同源、共边或共点邻接对象之间。该反趋势证明主要问题是合法共享接触的数值误判，不是远程表面或相向区域的真实穿插。

## 2. 根因

当前实现先通过 `tri_tri_overlap_test_3d(...)` 判断接触，再重新计算交点，最后使用严格浮点零判断确认交点是否位于允许的公共点或公共边：

```cpp
direction.cross(point - first).squaredNorm() == Scalar{0}
```

当顶面、侧面和源面接近共面时，平面求交产生的点包含舍入误差。合法公共边上的交点不再严格共线，于是 `EdgeTouch` 被分类为 `ProperIntersect`，`featureContainsEvidence(...)` 随后将其判为非法接触。步长越小，相关平面越接近共面，求交条件越差，因此误判反而增加。

单元测试使用轴对齐或数值整洁的坐标，无法覆盖这一真实输入尺度问题。

## 3. 方案比较

### 3.1 方案一：对拓扑邻接对象全部跳过

只要两个候选共享源点或源边，就完全不进行碰撞检测。速度最快，也能消除当前误判，但会漏掉凹角处越过公共边或公共侧面的真实穿插，因此不采用。

### 3.2 方案二：对交点包含判断增加统一容差

将严格零判断替换为尺度相关容差。改动较小，但容差会同时影响共线、共面、点在线段内和点在面内等多个判断，难以证明不会放过短尺度真实碰撞，也与当前不对外暴露碰撞容差的决定冲突，因此不作为主要方案。

### 3.3 方案三：拓扑优先检查非共享部分（采用）

先用 `CollisionVertexKey` 确定允许的公共点、公共边或公共面，再只检测共享特征之外的几何部分：

- 没有共享拓扑 key：继续执行完整三角形相交检测；
- 共享一个 key：忽略公共点本身，分别检查两个三角形的非共享对边是否进入另一个三角形；
- 共享两个相邻 key：公共边接触直接视为合法；仅检查非共享顶点、非共享边是否越过对方三角形内部；
- 完整边界面相同：该公共侧面合法，不把不同 Quad 对角线拆分造成的重叠当作碰撞；
- 坐标相同但拓扑 key 不同：仍按无共享拓扑处理，任何接触均非法。

该方法继承旧 `IntersecChecker::checkIntersect(...)` 的核心思想：一个共享点时检查两条非共享对边；两个以上共享点时不把公共边本身作为碰撞。新实现额外保留“非共享部分越界”的检查，避免旧实现 `same_count >= 2` 无条件放行造成漏检。

## 4. 模块边界与数据流

改动限制在 Spatial 接触适配层：

- `triangle_contact.cpp`：根据完整边界面的 `CollisionVertexKey` 建立共享特征，并判断非共享部分是否发生真实穿插；
- `collision_index.cpp`：继续只负责 AABB 粗筛和调用接触合法性判断，不加入 Growth 规则；
- `layer_collision_checker.cpp`：保持原始障碍、历史边界和同层候选三阶段流程不变。

不修改 `GrowthFront`、质量检查、停止传播、层数协调或输出结构，也不增加公共配置项。

## 5. 错误与安全语义

- 非有限坐标和退化三角形仍返回 `SpatialError`；
- 没有拓扑共享关系时保持当前严格检测；
- 仅公共特征内的接触合法，非共享部分进入对方内部仍返回非法碰撞；
- 不依据坐标相等建立合法连接；
- 不记录碰撞对象，最终仍只记录停止源面和 `FaceStopReason::Collision`。

## 6. 测试设计

### 6.1 RED 单元测试

增加非轴对齐、小高度的合法共享接触：

- 顶面—邻候选侧面共享下一层边；
- 候选侧面—自己的原始源面共享底边；
- 两个候选仅共享一个源顶点形成公共生长线；
- 将高度从 `0.1` 缩小到 `0.001` 后判定结果保持合法。

这些用例必须先在当前实现上失败。

### 6.2 真实穿插保护测试

保留相同拓扑 key，移动非共享顶点，使非共享边穿入另一个三角形内部，断言仍为非法。再覆盖坐标相同但 key 不同的接触仍为非法。

### 6.3 回归与真实案例

- 运行 Spatial、CollisionIndex、LayerCollisionChecker 专项测试；
- 运行 Debug 和 Release 全量 CTest；
- 运行 `2dot5_cf` 一层 `first_height=0.1`；
- 运行 `2dot5_cf` 一层 `first_height=0.001`；
- 再运行十层案例确认后续历史边界和非局部碰撞仍生效。

## 7. 验收标准

1. 小高度合法邻接单元测试稳定通过；
2. 非共享部分真实穿插测试继续失败并停止对应候选；
3. 无拓扑关联的接触行为不变；
4. `2dot5_cf` 首层的同源面、共边和共点数值误碰撞显著下降；
5. `first_height=0.001` 不再比 `0.1` 产生更多合法邻接误停；
6. Debug、Release 全量 CTest 均为 0 failed；
7. 不增加用户可配置碰撞容差。
